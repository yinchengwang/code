## 1. 目标与范围

## 3. 质量门禁与状态语义

### 3.1 状态定义（冻结）

| 状态 | 含义 | 能否进学习队列 |
|---|---|---|
| `todo` | 内容不足（算法题缺题面或用例；卡缺断言脚本） | 否 |
| `draft` | 内容存在但未通过自动校验 | 否 |
| `verified` | 自动校验通过（卡：断言脚本 + 变异测试；算法：参考解法全 AC + 负例被拒） | 是 |
| `rejected` | 校验失败或抽检打回，且已记录理由 | 否 |

`progress`（学习进度：`todo` / `in-progress` / `done`）与 `status`（内容完备度）是两根独立的轴，不合并。

### 3.2 loader B 状态规则变更

| 卡目录状态 | 旧行为 | 新行为 |
|---|---|---|
| 无 `README.md` | 跳过 | 跳过（不变） |
| 有 `README.md`、无 `main.py` | `draft` | `draft`（不变） |
| 有 `README.md` + `main.py`、**断言脚本存在** | `verified` | `verified` |
| 有 `README.md` + `main.py`、**断言脚本不存在** | `verified` | **`draft`（本次变更）** |
| 有 loader C 单元文件 | loader C 优先（不变） | loader C 优先（不变） |

理由：原设计把“已出版教材”视为可信内容、允许 `verified`，并把断言缺失视为另一根轴。但实际效果是
**无断言脚本的卡进了学习队列，点进去得到 `compile_error`**——学习者体验与“可学”定义都受损。
本次按「可学 = 能读 + 能判」收敛：缺断言即 `draft`，供给页把它列为缺口。

### 3.3 校验门禁

| 内容形态 | 通过条件 | 失败处置 |
|---|---|---|
| DB/AI 卡 | 断言脚本 `exit 0` **且** 变异测试使脚本失败 | `rejected` + 原因 |
| 算法题 | 参考解法全用例 AC **且** 负例被拒（`wrong_answer` / `runtime_error` / `timeout`） | `rejected` + 原因 |
| 环境缺失（缺 numpy / 缺解释器） | `skipped`（不算通过也不算失败） | 不改状态，明确提示原因 |

变异测试不可省：`exit 0` 只证明“没崩”，`assert True` 也能过；只有变异测试能证明断言在盯被测逻辑。

### 3.4 人工抽检

| 轨 | 抽样规则 |
|---|---|
| 数据库 | 每轨 10%；不足 10 个至少抽 1 个 |
| AI | 每轨 10%；不足 10 个至少抽 1 个 |
| 算法 | **按「来源 × 难度」分层，每层至少 5 题**，层内按比例抽 |

- 抽检结论只有两种：通过（记 `reviewed: true` / `reviewed_at`，状态不动）、打回（状态改 `rejected` + 记理由）。
- **打回后闭环**：修订内容 → 重新自动校验 → 重新进入抽检。
  **不因单题失败暂停整轨**；但因该层出现失败，**该层抽检量扩大**（默认扩大到原样本的 2 倍，最少 +5）。
- 最终样本量按实际存在的分层数公布，不预写死数字。

## 4. 内容补齐

### 4.1 DB / AI：29 张卡（25 张缺断言、29 张缺讲解）

| 项 | 做法 |
|---|---|
| 讲解正文 | LLM 依 `main.py` + `README.md` + `NOTES.md` 生成，落 `learning/units/<track>/<stem>.md` 的 `## 讲解` 小节。**29 张全缺，全都要补** |
| 断言脚本 | LLM 依 demo 与讲解生成，落同目录 `<stem>.assert.py`，独立文件、不动 `main.py`。**25 张缺，4 张已有** |
| 校验 | `verify` 跑真执行 + 变异测试 |
| 顺序 | **先 2 张试跑 → 人工看 → 放量到 25 张**（先验提示词质量，避免批量返工） |

新产物 `status` 从 `draft` 起；`source: generated`（与教材卡的 `source: grokking` 区分，便于追溯 LLM 产物）。

已有的 4 张断言脚本里，`mvcc` 与 `index_design` 变异测试未捕获 → 需修正后重验；`sql_fundamentals` 与
`transaction` 已通过，只需补讲解。

### 4.2 算法轨：687 道

| 项 | 做法 |
|---|---|
| 四件套 | 题面 / 测试用例 / 参考解法 / 负例，一次调用产一道 |
| 落点 | `learning/units/algorithm/`：`<stem>.md` + `<stem>.reference.cpp` + `<stem>.negative.cpp`；**存量 `learning/bank/**` 一字节不动** |
| 校验 | 真 `g++` 编译执行：参考解法全 AC、负例必须被拒 |
| 批处理 | 分批 + 断点续跑 + 单批/当日配额 + 最小间隔 + 单题重试上限，到顶即停并提示 `--resume` |
| 交付观测 | 每批报告：新增 verified / rejected / 仍 todo / 待抽检；`report` 打出全轨欠账 |

### 4.3 写盘纪律（全轨）

- 写回前查脏：目标仓工作区不干净则拒绝写回并指出文件。
- 只改目标行/目标小节：整份单元文件其余字节（含换行风格）不变。
- **绝不自动 `git add` / `git commit`**：只打印 diff，提交由人决定。

## 5. 环境配置：统一判题解释器

### 5.1 问题

判题、环境自检、loader 警告、离线校验各自探测解释器，出现三处不一致：
默认探测拿到无 numpy 的 `python`，而 `py -3` 有 numpy。结果是「自检说缺 numpy、
但换成 `py -3` 又能跑」，且 Web 上无从切换（设置写入白名单不含该键）。

### 5.2 设计

```
唯一配置源：settings 表 judge.python.cmd
优先级：ctx 注入（测试）> settings.judge.python.cmd > STUDY_HUB_PYTHON > 自动探测
```

- 判题（单元页 `/api/units/:id/judge`、会话 `/api/session/submit`）、`/api/env`、
  `GET /api/settings` 的环境段、loader B 的 numpy 警告、离线 `supply verify` **全部读同一配置**。
- `PUT /api/settings` 白名单**新增** `judge.python.cmd`：接受形如 `python` / `python3` / `py -3` 的
  解释器命令；写入前做一次探测，探测不到就 400 拒绝并给出中文原因（不写入无效配置）。
- 设置页加「判题解释器」输入框 + 当前生效解释器与 numpy 状态显示；保存后立即重探。
- **不自动安装依赖**：NumPy 缺失只报状态与解决方式（换解释器 / 自行安装），不执行安装命令。

## 7. LLM 密钥与降级

### 7.1 密钥纪律（沿用并强化）

- 密钥只从环境变量或 `apps/study-hub/.env` 读；**已存在的环境变量优先，`.env` 不覆盖**。
- 密钥**不进**代码、settings 表、单元文件、生成产物、git（`projects/.gitignore` 已忽略 `.env`）。
- CLI 不接受 `--api-key` / `--token` / `--secret` 之类参数，解析到即报错退出。
- 提供 `.env.example`（键名 + 注释，无真实值），README 指向它。

### 7.2 降级

| 状态 | 行为 |
|---|---|
| 无密钥 / LLM 关 | 学习、判题、复习、诊断、`plan` / `verify` / `review` / `report` 照常可用；`generate` 退出码 2 + 中文提示 |

| 配额到顶 | 立刻停并提示“用 `--resume` 接着跑”，不继续烧额度 |

### 7.3 联调时点

## 9. 风险与已知代价

1. **可学单元骤减**：R1 落地到 R2 完成之间，DB 轨 2 张、AI 轨 0 张。这是严格口径的正确结果，需在 UI 上明示“需要新题”而非报错。
2. **LLM 成本与耗时**：687 道 + 25 张卡是真实调用，受配额与限流约束；按批推进，进度可观测。
3. **内容质量残留**：变异测试挡“假通过”，挡不住“断言写对了但考的不是重点”；靠分层抽检兜底，残留错误会存在。
4. **状态门槛变更的回归面**：`verified` 语义收紧会影响候选池、诊断分母、供给计数、既有测试断言；必须同步契约与测试，避免两套口径并存。
5. **既有副作用**：`supply verify` 会**创建** `learning/units/*.md`（当前实现如此）。作业顺序上必须先明确该行为是否保留，否则诊断与真实内容会混在一起（本次已按“保留但讲解写占位符”处理）。
6. **环境差异**：Windows 下解释器探测顺序与 numpy 分布不一致；仅靠配置收敛，不保证跨机器一致。
